* Installing
:PROPERTIES:
:ID:       9CD67B2F-AEAB-487C-8A31-9CF2F9D29C62
:END:

The install script performs the following steps:

1. ensures the dotfiles are present in the user's home directory.
2. ensures that host's package manager is up to date
3. ensures that the host system has the prerequisite software
   installed - =git=, =stow=, etc. If a dependency is missing, the
   install script attempts to resolve the missing dependency through the
   system's package manager.
4. places configuration via GNU Stow.

** Locally via git and the =install= script

#+BEGIN_SRC sh
$ git clone git@github.com:indiebrain/.files.git ~/.files
$ ~/.files/install
#+END_SRC

* How this project works
:PROPERTIES:
:ID:       627304DE-BAA2-4227-BCCE-AE768D10DA41
:END:

 On-disk configuration is contained exclusively with the dotfiles
project directory (usually =~/.files=) in a layout which can easily be
managed by GNU Stow. GNU Stow symlinks the configuration into place
outside the dotfiles project to minimize the project's impact on the
host file system.

* Uninstalling
:PROPERTIES:
:ID:       98916F17-8D18-486E-BC26-822E146778A7
:END:

This dotfiles repository is self-contained, all configuration lives
inside the root - files should NOT be placed outside of the dotfiles
home directory (usually =~/.files=) on the host file system.

The use of GNU Stow affords the ability to "Soft
Uninstall" the configuration provided herein by removing the symbolic
links to the configuration content - IE the configuration can
be moved out of the way of the host while the source still lives on
disk. The =uninstall= script will do just this.

To completely remove these dotfiles:

1. run the =uninstall= script
2. remove the dotfiles home directory (usually =~/.files=) from the
   local file system - via =rm -rf=

* Packages

Each top-level directory is a GNU Stow "package" whose internal layout
mirrors the home directory. The =install= script stows every package in
the repository except =rectangle=, and stows =ollama= only on macOS (see
below). To place a single package
by hand - for example after adding a new one - run GNU Stow from within
the dotfiles home directory:

#+begin_src sh
$ stow PACKAGE
#+end_src

** =rectangle=

The =rectangle= directory holds =RectangleConfig.json=, an exported
configuration for the [[https://rectangleapp.com/][Rectangle]] window
manager. Rectangle keeps its live preferences in the macOS defaults
system rather than a file GNU Stow can symlink, so this package is NOT
stowed by =install=. Apply it by hand from Rectangle's menu -
=Settings -> Import...= - and select =rectangle/RectangleConfig.json=.

** =ollama=

The =ollama= directory holds =com.aaron-kuehler.ollama.plist=, a
user-owned launchd agent that runs the Ollama server with tuned memory,
context, and concurrency settings. It replaces the Homebrew-managed
service, which regenerates its own plist on every =brew services= action
and upgrade and so cannot carry custom environment variables. The plist's
leading comment holds the memory sizing and the reload commands.

launchd is macOS-only, so =install= stows this package only on Darwin.
GNU Stow links the plist rather than copying it, and launchd resolves the
link when the agent is bootstrapped. After editing the plist, reload the
file itself; =launchctl kickstart= restarts the process from the
configuration launchd already holds, which ignores the edit:

#+begin_src sh
$ launchctl bootout gui/$(id -u)/com.aaron-kuehler.ollama
$ launchctl bootstrap gui/$(id -u) ~/Library/LaunchAgents/com.aaron-kuehler.ollama.plist
#+end_src

The =OLLAMA_*= exports in the =bash= package apply only to a hand-run
=ollama serve=. The two sets are kept in sync by hand.

** =herdr=

The =herdr= directory holds =.config/herdr/config.toml=, the settings for
herdr: theme selection and light/dark switching, toast delivery, and how
agent panes are labeled and sorted.

herdr keeps its running state beside that file in the same directory:
logs, Unix domain sockets, the current session, cached release notes, and
a plugin lock file. Those are generated per host and change constantly, so
the package ignores them and tracks only =config.toml=.

** =scripts=

This package contains a number of utility shell scripts. When stowed via
=stow scripts=, it is linked into the =$HOME/bin= directory. This
directory is automatically included on the user's path so all scripts
should be immediately discoverable by Bash.
